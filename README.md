# 巡展作品光照预算 Web 工作台

为巡展作品管理展期曝光预算的本地 Web 工具：Node.js + SQLite + 浏览器页面，单机本地运行。

- **作品维度**：录入展期曝光上限与既有累计量，实时显示已用 / 预占 / 余额（单位 lux·min）。
- **时段维度**：为展厅时段录入起止时间、照度（lux）和展出作品，按 **实际经过分钟 × 照度** 计算曝光。
- **整批排期**：未开始时段在草稿中统一编辑后整批提交；同一作品时段重叠、或“已用 + 预占”超上限时 **拒绝整批**，逐条指出冲突作品与时段。
- **生命周期**：时段开始即冻结原排期并保留预占；结束时补记实际起止与照度，**实际曝光替换该时段预占**；结算超量后按开始时间/编号顺序标出不可启动时段与缺口并禁止启动。
- **多段照度**：巡展现场实际照度可能随时间变化。进行中时段可用**实际起止 + 多段照度**结算，每段含起止与非负照度，按 `Σ 实际分钟 × 照度` 求和；分段必须首尾衔接、无重叠且完整覆盖实际区间，否则整批拒绝。
- **结算更正**：已结束时段可按**原实际起止**提交带理由的完整分段更正；系统记录更正前后的曝光与时间，新总量替换旧总量（不重复累计），并同步重算作品已用量、后续时段不可启动状态与缺口。
- **乐观并发**：所有调整携带当前版本号，过期版本返回 409 与最新预算。

## 一键启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

启动后打开：

- **页面地址**：http://localhost:8080
- 初始化：首次启动自动建表并写入演示数据（3 件作品 + 已结束/进行中/未开始时段）。

如需更换宿主机端口：

```bash
PORT=9090 docker compose up -d --build   # 页面变为 http://localhost:9090
```

停止与重置初始数据：

```bash
docker compose down            # 停止，数据保留在命名卷中
docker compose down -v         # 同时删除数据卷，下次启动重新初始化
```

## 本地直接运行（需要 Node.js ≥ 20）

```bash
npm install
npm start
# 打开 http://localhost:8080
```

## 配置（环境变量）

| --- | --- | --- |

## 计算与校验规则

- **曝光量** = （结束 − 开始，分钟）× 照度 lux，单位 **lux·min**。
- **多段结算曝光量** = 各分段「（段结束 − 段开始，分钟）× 该段照度」之和；每段照度必须为非负数值。
- **分段衔接校验**（多段结算与更正共用，任一不满足则整批拒绝）：
  1. 至少一段，每段结束必须晚于段开始，照度非负；
  2. 首段开始必须等于实际开始 `actualStart`，末段结束必须等于实际结束 `actualEnd`；
  3. 相邻分段必须首尾衔接（上一段结束 = 下一段开始），系统据此同时识别**缺口**与**重叠**并逐条报错。
- **已用** = 作品既有累计量 + 所有已结束时段的**实际**曝光（多段时取分段求和值）。
- **预占** = 进行中时段的（冻结）计划曝光 + 所有未开始时段的计划曝光之和。
- **余额** = 上限 − 已用 − 预占；余额为负即超量。
- 排期整批保存时校验：
  1. 时间格式合法、结束晚于开始、照度/累计量非负（无效时序或负值一律拒绝）；
  2. 同一作品在任意两个未开始时段、以及与进行中（冻结区间）/已结束（实际区间）时段之间不得重叠；
  3. 每件作品「既有 + 已结束实际 + 进行中预占 + 本批未开始预占」不得超过展期上限。
- 任一条不满足则整批不落库，响应中给出作品、冲突时段对或超量数值。
- **不可启动核算**：每次调整/启动/结算/**更正**后，未开始时段按开始时间（再按编号）顺序尝试占用预算；任一关联作品余额不足即标记为“不可启动”并列出每件作品的可用余额、需求与缺口，启动接口对该时段返回 422。调整排期保存后自动重新核算。
- **结算更正规则**（仅已结束时段）：必须填更正理由；更正只能重新切分照度分段，**实际起止沿用原结算值**，分段须完整覆盖该区间；新曝光总量替换旧总量（不会在旧值上累加），更正记录保留每次的理由、更正前后起止/照度/曝光与完整分段；作品已用量与后续不可启动状态、缺口同步重算。
- **并发版本**：每次成功变更版本号 +1。变更请求必须携带当前 `version`（多段结算 `settle` 与更正 `correct` 同样要求）；不匹配时返回 `409 VERSION_STALE` 与最新完整预算，**失败不改变结算和版本**，前端自动刷新后需重新调整提交。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 最新版本、作品预算汇总、全部时段及不可启动核算结果 |
| POST | `/api/artworks` | 录入作品（body 带 `version`） |
| PUT | `/api/artworks/:id` | 修改作品上限/既有量等 |
| DELETE | `/api/artworks/:id` | 删除作品（被时段引用时拒绝） |
| POST | `/api/schedule` | **整批替换未开始时段**（body：`{version, slots:[...]}`） |
| POST | `/api/slots/:id/start` | 启动时段：冻结原排期、保留预占 |
| POST | `/api/slots/:id/finish` | 结束补记（兼容保留）：`{actualStart, actualEnd, actualLux}`，实际曝光替换预占并重新核算 |
| POST | `/api/slots/:id/settle` | **多段照度结算**（进行中）：`{version, actualStart, actualEnd, segments:[{start,end,lux}]}` |
| POST | `/api/slots/:id/correct` | **已结束时段分段更正**：`{version, reason, segments:[...]}`，按原实际起止覆盖，返回更正前后曝光/时间 |

`GET /api/state` 的每个时段对象额外包含：

- `actualSegments`：实际照度分段数组 `[{index, start, end, lux, minutes, exposure}]`（单照度结算/旧数据也呈现为一段）；
- 多段结算后 `actualLux` 为 `null`（逐段照度见 `actualSegments`），单段时为该段照度；
- `corrections`：更正记录数组，每条含 `reason`、`createdAt`、`version` 以及 `before` / `after` 的起止、照度（多段为 `null`）、曝光与完整 `segments`。

### HTTP 调用示例（curl）

多段照度结算（进行中时段 #2，9:00–11:00 为 100 lux、11:00–13:00 为 350 lux）：

```bash
curl -X POST http://localhost:8080/api/slots/2/settle \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 1,
    "actualStart": "2026-09-30T09:00",
    "actualEnd":   "2026-09-30T13:00",
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 100 },
      { "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 350 }
    ]
  }'
# 120×100 + 120×350 = 54000 lux·min；返回最新预算 + justFinishedExposure + blockedAfterFinish
```

分段不衔接 / 未覆盖实际区间 / 照度为负 → `422 SEGMENTS_INVALID`，`errors` 逐条说明；版本缺失或过期 → `409 VERSION_STALE` 并附 `state` 最新预算。

已结束时段分段更正（实际起止沿用原结算，仅重新切分照度，必须带理由）：

```bash
curl -X POST http://localhost:8080/api/slots/2/correct \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 2,
    "reason": "现场照度计分段补录",
    "segments": [
      { "start": "2026-09-30T09:00", "end": "2026-09-30T11:00", "lux": 200 },
      { "start": "2026-09-30T11:00", "end": "2026-09-30T13:00", "lux": 300 }
    ]
  }'
# 返回 correction.beforeExposure / afterExposure（54000 -> 60000）及最新预算；
# 新总量替换旧总量（不重复累计），作品已用量、后续不可启动状态与缺口同步重算
```

旧的单一照度结束补记完全保持可用（无需版本号，返回语义不变），落库时同样保存为一段：

```bash
curl -X POST http://localhost:8080/api/slots/2/finish \
  -H 'Content-Type: application/json' \
  -d '{ "actualStart": "2026-09-30T09:00", "actualEnd": "2026-09-30T13:00", "actualLux": 200 }'
```

## 页面用法（本轮新增）

- **进行中时段结束补记**：弹窗顶部可切换「单一照度结算 / 多段照度结算」。多段模式填写实际起止后逐段添加 `段开始 ～ 段结束 + 照度`，页面实时显示每段曝光与合计；提交前校验首尾衔接与完整覆盖，不通过会逐条提示。
- **已结束时段**：操作列点击「▸ 分段/更正」展开**实际照度分段表**与**更正记录**（理由、时间、更正后版本、前后起止/照度/曝光，可展开查看更正后分段）。
- **分段更正**：点击「分段更正」，实际起止固定显示为原结算值且不可改；填写理由（必填）后编辑完整分段，页面实时显示合计曝光与「较原总量」差值；提交成功后新总量替换旧总量，作品已用量与后续不可启动标记同步刷新。
- 多段结算与更正均携带当前版本；遇到 409 页面会自动载入最新预算，需重新操作。

## 快速体验超量拦截

初始演示数据以 2026-09-30 为当天，预算均充足。进入页面：

1. 对「一号厅 09:00–13:00（进行中）」点 **结束补记**；
2. 把实际照度改为 `300`（240 分钟 × 300 = 72000 lux·min），保存；
3. 后续二号厅时段会被标记为 **不可启动**，页面列出《山水轴》《星夜手稿》的缺口，启动按钮被禁止；
4. 在未开始排期草稿中缩短时长 / 降低照度 / 改展作品后 **整批校验并保存**，缺口消除即可重新启动。
